# Sub-project A — Bootstrap (lem + qlot launcher)

**Date:** 2026-05-07
**Status:** Approved design, not yet implemented
**Scope:** First of five sub-projects. See `CLAUDE.md` for the A→B→(C,D,E) decomposition.

## Goal

Stand up the minimum scaffolding so that running `bin/phaverlite-ide` launches
lem-ncurses with our project-local configuration, while leaving the user's
`$HOME` untouched.

## First-time setup

After cloning, the developer runs **once**:

```sh
qlot install     # populates ./.qlot/ from qlfile.lock
```

This is a one-time bootstrap step, not part of every launch. The launcher
script (`bin/phaverlite-ide`) assumes `./.qlot/` already exists.

## Definition of done

1. `qlot install` (run once after fresh clone) succeeds and populates `.qlot/`.
2. `bin/phaverlite-ide` launches lem-ncurses in the current terminal.
3. The lem `*Messages*` buffer contains the line
   `[phaverlite-ide] sub-project A bootstrap loaded`,
   proving `config/init.lisp` was the one that ran.
4. After exit, `bin/verify-isolation` reports zero new files and zero mtime
   changes under `~/.config/lem/`, `~/.cache/lem/`, `~/.lem/`, `~/.qlot/`,
   and `~/.sbclrc`.

Out of scope for A: `.pha` major mode, LSP, pc-sweep UI, plot generation,
opening files via CLI args, automated CI smoke tests.

## Architecture

Three layers; each has one job.

```
┌──────────────────────────────────────────────────────┐
│ bin/phaverlite-ide   (zsh script)                    │
│   • Resolve repo root from $0                        │
│   • Set env: LEM_HOME, XDG_{CONFIG,DATA,CACHE}_HOME  │
│     → all under $REPO/var/                           │
│   • Verify `qlot` is on PATH                         │
│   • exec qlot exec sbcl --no-userinit --no-sysinit  │
│         --load config/init.lisp                      │
└─────────────────────┬────────────────────────────────┘
                      │
┌─────────────────────▼────────────────────────────────┐
│ config/init.lisp                                     │
│   • (ql:quickload :lem-ncurses)                      │
│   • Register *after-init-hook* that prints banner    │
│   • (lem:lem)                                         │
└─────────────────────┬────────────────────────────────┘
                      │
┌─────────────────────▼────────────────────────────────┐
│ qlfile / qlfile.lock   (qlot manifest, repo root)    │
│   • git lem .../lem.git :ref <SHA verified on Mac>   │
│   • Transitive deps resolved by qlot                 │
└──────────────────────────────────────────────────────┘
```

## Environment isolation

The launcher exports the following before `exec`-ing qlot/sbcl. All paths
are inside the repo (`$REPO/var/...`). `var/` is gitignored.

| Variable | Value | Purpose |
|---|---|---|
| `LEM_HOME` | `$REPO/var/lem` | Lem's per-user state. Without this, lem falls back to `~/.lem/` or `~/.config/lem/`. |
| `XDG_CONFIG_HOME` | `$REPO/var/xdg-config` | Catches any XDG-aware library that would otherwise write to `~/.config/`. |
| `XDG_DATA_HOME` | `$REPO/var/xdg-data` | Catches `~/.local/share/` writes. |
| `XDG_CACHE_HOME` | `$REPO/var/xdg-cache` | Catches `~/.cache/` writes from libraries used during the lem session. Note: this does **not** affect qlot's download cache at `~/.cache/qlot/`, because that cache is hit only during `qlot install` (a separate one-time step), not during `qlot exec` at launch. So CLAUDE.md's "let `~/.cache/qlot/` function normally" rule is preserved. |
| `HOME` | **unchanged** | Remapping `$HOME` would break ssh, git, terminal config. Isolation comes from XDG/LEM_HOME, not from hiding `$HOME`. |

`sbcl --no-userinit --no-sysinit` ensures `~/.sbclrc` and the system sbclrc
are not loaded. qlot manages ASDF source registry, so we don't set
`CL_SOURCE_REGISTRY` ourselves.

`~/.qlot/local-projects/` is **never written to**. `qlot install` writes
only to `<repo>/.qlot/` by default, so this is upheld by simply not
running `cp` or `qlot add --global`.

## Files added by this sub-project

```
bin/
  phaverlite-ide        # launcher (zsh)
  verify-isolation      # pre/post snapshot of $HOME state (zsh)
config/
  init.lisp             # ~20 lines, content below
qlfile                  # one git entry pinning lem to a verified SHA
qlfile.lock             # generated by `qlot install`, committed
var/
  .gitkeep              # ensure dir exists in fresh clones
```

`.gitignore` is updated to add `var/*` and `!var/.gitkeep`.

## `config/init.lisp` (full content)

```lisp
;;;; config/init.lisp — PHAVerLite IDE bootstrap, sub-project A.
;;;; Loaded by bin/phaverlite-ide via `sbcl --no-userinit --no-sysinit --load`.
;;;; Job: prove the launcher boots lem-ncurses with our config and nothing else.

(in-package #:cl-user)

(ql:quickload :lem-ncurses :silent t)

;; Verification banner — appears in *Messages* so we can confirm THIS init.lisp
;; ran (vs. some stray ~/.config/lem/init.lisp). Used by bin/verify-isolation.
(defparameter *phaverlite-ide-banner*
  "[phaverlite-ide] sub-project A bootstrap loaded")

;; Defer the message until lem is up, then start the editor.
(lem:add-hook lem:*after-init-hook*
              (lambda () (lem:message *phaverlite-ide-banner*)))

(lem:lem)
```

## `qlfile`

```qlfile
# qlfile — qlot manifest, repo-relative install into ./.qlot/
# Pinned to a specific commit verified to build with qlot + ncurses on Mac.
git lem https://github.com/lem-project/lem.git :ref <SHA-TBD-during-impl>
```

The placeholder `<SHA-TBD-during-impl>` is resolved during implementation:

1. `git ls-remote https://github.com/lem-project/lem.git main`
2. Set `:ref` to that SHA in qlfile.
3. `qlot install` and try `(ql:quickload :lem-ncurses)` in `qlot exec sbcl`.
4. If it builds clean and `(lem:lem)` starts, commit the SHA. Otherwise walk
   back commit-by-commit on main until one builds.

No other entries are added unless a transitive dep at HEAD-of-its-dist is
broken; in that case add a `git ... :ref <known-good-sha>` override for
that one library.

## Tooling assumption

`qlot` (Roswell-installed at `~/.roswell/bin/qlot`) must be on `PATH`. The
launcher checks this with `command -v qlot >/dev/null` and exits with a
clear message if absent. We do not bootstrap qlot itself.

## Verification mechanism

`bin/verify-isolation` is a small zsh script for manual checking. It:

1. Snapshots `find ~/.config/lem ~/.cache/lem ~/.lem ~/.qlot -type f -newer /tmp/before 2>/dev/null` — actually, simpler: `touch /tmp/before-launch`, then after the user exits lem, `find` for files newer than that timestamp under those paths.
2. Reports any new or modified files.
3. Also `stat ~/.sbclrc` before and after (if it exists).

Not wired into CI for the prototype. Run manually after first launch and
after any change to the launcher or init.lisp.

## Privacy / public-repo considerations

This sub-project produces only path-handling and config glue — no risk of
leaking personal data, but per `CLAUDE.md` rules:

- `bin/phaverlite-ide` derives the repo root with `$(cd "$(dirname "$0")/.." && pwd)`. **No hardcoded `/Users/...` paths.**
- `bin/verify-isolation` uses `$HOME`, never the literal username.
- `config/init.lisp` contains no user-specific data.
- `qlfile` references only the public lem GitHub URL.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Latest lem main doesn't build cleanly with current qlot | Pin to last-known-good SHA; documented in this spec under §`qlfile`. |
| `qlot exec sbcl` finds the wrong sbcl (system vs. roswell) | Don't override; qlot uses `sbcl` from PATH. Document expected sbcl version in implementation plan if it matters. |
| Lem reads a config file we forgot to override | `bin/verify-isolation` catches it on the next manual run; add the var to the launcher when found. |
| Future webview migration invalidates the launcher | Acceptable — webview migration is a future sub-project and gets its own design. The ncurses launcher stays as a fallback. |
